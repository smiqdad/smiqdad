- Practical automation for support and internal operations

## Featured projects

### [Support Workflow Evaluation Lab](https://github.com/smiqdad/support-workflow-evaluation-lab)

A synthetic, inspectable demonstration of how support conversations can be validated, classified, routed, and evaluated before an AI system is allowed to draft a response.

It demonstrates deterministic policy rules, approved-source requirements, authentication checks, abstention, human handoffs, regression cases, and automated testing. All data, companies, policies, and conversations are fictional.

### [Implementation Readiness Workbench](https://github.com/smiqdad/implementation-readiness-workbench)

A synthetic product interface for comparing a customer's desired operating state with its configured live state before launch.

It demonstrates evidence-backed readiness rules, visible blockers, exception ownership, accountable approvals, audit history, responsive interaction design, and automated tests. All companies, people, requirements, evidence, and decisions are fictional.

## How I approach the work

I care about whether a workflow solves the underlying operational problem—not merely whether an AI model can produce plausible output. That means making decision rights, sources of truth, failure modes, evaluation criteria, and human controls visible from the beginning.
